# OriBrink 12 周执行任务表（2026）

目标：
1. 12 周内跑通“数据 -> 特征 -> 策略 -> 回测 -> 盘前清单 -> 复盘”闭环。
2. 至少上线 2 个可迭代策略模板（弱转强、潜龙在渊）。
3. 形成稳定周节奏与版本管理机制。

## 1. 里程碑总览

1. 第 1-4 周：最小闭环（MVP）
2. 第 5-8 周：可用性增强（L1/L2 + 看板 + 周报）
3. 第 9-12 周：稳定性与实战支持（提醒 + 健康度 + 组合）

## 2. 角色建议

1. 策略负责人：定义规则、审核样本、确认上线。
2. 量化研发：数据、特征、回测、调度。
3. Web/API：接口、看板、交互。
4. 执行与复盘：交易日志、案例沉淀、反馈闭环。

## 3. 周任务拆解

### Week 1：项目骨架与规范
交付：
1. 初始化目录结构（services/shared/web/docs）。
2. 建立基础工程规范（lint、format、env 模板）。
3. 建立 PostgreSQL 与 Redis 本地环境（docker compose）。
4. 建立任务调度框架骨架（APScheduler/Celery 二选一）。
5. 建立统一 `uv` 工作流（依赖同步、脚本命令、启动入口）。

验收：
1. 本地一键启动成功。
2. 健康检查接口可用。
3. 通过 `uv run` 启动 API 与调度任务。

### Week 2：市场数据入库（Daily）
交付：
1. `md.symbol_master`、`md.symbol_daily` 建表。
2. 日线拉取任务与增量更新。
3. 基础数据质量校验（缺失、重复、范围异常）。
4. job 运行日志入 `sys.job_runs`。

验收：
1. 最近 1 年日线数据可按代码/日期查询。
2. 每日任务成功率记录可见。

### Week 3：竞价与 L0 特征
交付：
1. `md.auction_snapshot` 建表及采集任务。
2. `ft.feature_l0_baseinfo` 计算逻辑实现。
3. 生成 `sys.data_snapshots` 版本记录。
4. 首个特征核对脚本（抽样比对）。

验收：
1. 任一交易日可查 L0 特征。
2. 特征计算可重复运行，结果一致。

### Week 4：首个策略 + 日频回测 MVP
交付：
1. 策略接口冻结（generate_signals 标准输入输出）。
2. 弱转强策略 v0 接入。
3. 回测 MVP（含手续费、滑点、T+1）。
4. 回测结果落库（`bt.backtest_*`）。

验收：
1. 可对弱转强完成近 2-3 年回测。
2. 输出收益、回撤、胜率、盈亏比。

### Week 5：盘前候选池 v0
交付：
1. 盘前任务 `job_pre_market_selection`。
2. `st.signal_results`、`st.pre_market_candidates` 落库。
3. 候选清单 CSV 导出。
4. FastAPI 查询接口（按日期、排名、策略）。

验收：
1. 每天可自动生成候选池（20-50）。
2. 候选包含命中原因与风险标签。

### Week 6：看板 v0 + 交易日志
交付：
1. Web 页面：候选池列表、详情页。
2. 交易日志录入 API + 页面。
3. `rt.manual_trade_logs` 入库。
4. 基础权限（最小鉴权）。

验收：
1. 团队可在页面查看候选与录入实操。
2. 可按日期导出交易日志。

### Week 7：L1/L2 特征接入
交付：
1. `ft.feature_l1_market_stats`、`ft.feature_l2_behavior_score` 计算。
2. L1/L2 质量校验报表。
3. 特征版本管理机制（feature_version）。
4. 策略读取 L1/L2 的统一方法。

验收：
1. 最近 80 日滚动特征可查询。
2. 策略可基于 L1/L2 打分。

### Week 8：潜龙在渊策略 v0 + 多策略融合
交付：
1. 潜龙在渊策略实现（参数外置）。
2. 多策略融合打分（可配置权重）。
3. 策略版本管理页面/API。
4. 回测对比报告（弱转强 vs 潜龙在渊 vs 融合）。

验收：
1. 至少 2 套策略可独立运行。
2. 候选池支持多策略融合排序。

### Week 9：盘中提醒 v0
交付：
1. 分钟级轮询/订阅任务。
2. 提醒规则模板（价格、量能、封板状态）。
3. 提醒事件入库与前端展示。
4. 人工标记（忽略/关注/执行）。

验收：
1. 触发到展示延迟可观测。
2. 提醒历史可回查。

### Week 10：复盘中心与周报自动化
交付：
1. `rt.review_cases` 模块上线。
2. 自动周报任务：成功/失败/错过样本统计。
3. 策略失效样本 TopN 报告。
4. 周会使用模板文档。

验收：
1. 可一键生成周报。
2. 每条复盘样本可关联策略版本。

### Week 11：稳定性测试与风控规则
交付：
1. 参数扰动测试（稳定性评分）。
2. 策略健康度分级（继续/降权/停用）。
3. 基础组合仓位规则（按健康度上限）。
4. 异常策略自动告警。

验收：
1. 至少 2 个策略完成稳定性评估。
2. 形成可执行的停用机制。

### Week 12：联调封版与实战切换
交付：
1. 全链路联调与性能检查。
2. 关键任务失败兜底方案（手工补跑/重试）。
3. 操作手册（盘前/盘中/盘后 SOP）。
4. 版本封版（v1.0）与下阶段 backlog。

验收：
1. 连续 5 个交易日流程稳定运行。
2. 团队按 SOP 完成闭环，无关键阻塞。

## 4. 每周固定节奏（建议）

1. 周一：确认本周策略白名单与目标。
2. 周二-周五：执行 + 记录 + 小步迭代。
3. 周六：复盘与回测。
4. 周日：参数冻结与下周计划。

## 5. 标准命令（统一为 uv）

环境初始化：
1. `cp .env.example .env`
2. `bash scripts/bootstrap.sh`
3. `docker compose up -d`

日常开发：
1. 启动 API：`uv run oribrink-api`
2. 启动调度器：`uv run oribrink-scheduler`
3. 代码检查：`uv run ruff check .`
4. 类型检查：`uv run mypy services shared`
5. 测试：`uv run pytest`

## 6. 每周输出模板（最小化）

每周必须提交：
1. 本周新增/变更策略列表。
2. 回测结果摘要（收益、回撤、样本外表现）。
3. 失败样本 Top 5 与改进动作。
4. 下周任务清单（可执行、可验收）。

## 7. 风险与应对

1. 数据源不稳定
- 应对：缓存备份源 + 失败重试 + 缺失告警。

2. 回测与实盘偏差大
- 应对：增强滑点/成交约束建模，记录偏差反哺。

3. 任务堆积导致盘前超时
- 应对：任务分层并行 + 预计算 + 热点缓存。

4. 团队节奏断档
- 应对：固定周会与模板化输出，避免口头协作。

## 8. 12 周结束的硬性验收

1. 盘前候选池每天可稳定输出。
2. 至少 2 个策略可追溯、可回测、可迭代。
3. 盘中提醒和盘后复盘都已上线并被使用。
4. 周报机制稳定，策略健康度可量化。
